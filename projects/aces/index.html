A.C.E.S — Agentic Control System

A rigorous, phased experiment testing whether multi-agent LLM systems can make trading decisions worth trusting — specialized agents read indicators, chart patterns, and trend structure in parallel, weighed by a decision agent, with four architectures and two model choices tested head-to-head before any of it touches real capital.

Not "can an LLM sound like a trader" — can four different multi-agent architectures, tested against each other under the same conditions, produce decisions worth risking capital on.

Why I built this

I've traded long enough to know what a good decision under uncertainty actually looks like — and how different that is from a confident-sounding paragraph. So when agentic AI systems started getting proposed as autonomous traders, I didn't want another demo of an LLM narrating a trade. I wanted to know, specifically: given the same chart, the same indicators, the same market moment, does a multi-agent system built to read them arrive at a decision a competent discretionary trader would actually stand behind? And if more than one architecture can do this, which one — and does the underlying model even matter as much as the framework wrapped around it?

That's the honest version of "can agentic AI replace a human trader here." Not a yes/no. A measured one, on a real instrument, with real money-shaped consequences if the answer's wrong — which is exactly why I built the harness before I trusted any of it.

Four specialists, one verdict

Every decision — LONG, SHORT, or HOLD on USDJPY, hourly — passes through the same four-stage read regardless of which architecture is running it:

  • Indicator — RSI, MACD, Stochastic, ROC, Williams %R, ATR, Bollinger — computed for real, not estimated by the model, and handed over as numbers.
  • Pattern — a rendered candlestick chart, read by a vision-capable model for classical reversal/continuation formations — the model looks at the actual image, not a text description of it.
  • Trend — the same chart, now annotated with fitted support/resistance lines, read for structure and with/counter-trend positioning.
  • Decision — weighs all three reads into a directional call, a risk-reward ratio, and an ATR-scaled stop — the number that actually gets risked.

What changes between architectures is how those four stages talk to each other — a parallel LangGraph pipeline, an AutoGen debate where the specialists cross-examine each other, a DSPy program whose prompts are optimized against realized P&L instead of hand-tuned, and a LangGraph variant where a fifth agent reflects on the decision before it ships.

From a relay to a fan-out

The LangGraph baseline didn't start as parallel. This project builds on QuantAgent (the GitHub repo has since been renamed QuantHarness; the paper itself is still titled QuantAgent), a price-driven multi-agent trading system out of Stony Brook University — its reference implementation runs Indicator, Pattern, and Trend as a strict relay, each one waiting on the last before the Decision Maker ever sees anything:

Indicator, Pattern, and Trend don't depend on each other's output — only the Decision Maker needs all three. Restructuring the graph so they fan out from START simultaneously instead of chaining sequentially cut end-to-end latency by roughly 28%, with no change to what any individual agent sees or does. Same four specialists, same prompts — just no longer waiting in line.

Worth noting honestly: the QuantAgent paper never explains the sequential choice — I read through the full paper specifically checking for this, and "parallel," "sequential," "concurrent," and "simultaneously" don't appear in it in this context at all. The paper repeatedly frames low latency as a core motivation for the whole approach, which makes the sequential default a bit of a missed opportunity rather than a considered tradeoff — three independent reads with nothing to wait on each other for is about as free a latency win as this kind of system gets.

One variable at a time, or the result means nothing

The trap here is obvious in hindsight: if you swap both the model and the architecture at once and the numbers change, you've learned nothing about which one caused it. So the whole study is sequenced to isolate exactly one variable per phase:

  1. Phase 0 — Baseline & repeatability (done). Five identical runs of the current model mix over the same week, before comparing anything — to find out how much a single model's own results move around on nothing but ordinary LLM nondeterminism, before that noise gets mistaken for a real signal later.
  2. Phase 1 — Model, architecture held constant (in progress). DeepSeek + Gemini vs. all-MiniMax-M3, both on the same LangGraph pipeline, same window, five replicates each.
  3. Phase 2 — Architecture, model held constant (pending). Whichever model wins Phase 1, tested across all four architectures. Each one now runs its own full pipeline independently — nobody reuses another system's analysis, so cost and latency are honestly comparable, not just decision quality.
  4. Phase 3 & 4 — Re-sweep, then check for interaction (pending). Re-optimize the winning architecture per model, then re-run the model swap on the second-best architecture — if the ranking flips, model and architecture interact, and the one-at-a-time result alone would have been misleading.

What "better" has to mean before I trust it

Phase 1 is where I decide between the current mix and MiniMax-M3. I set three criteria before running anything, specifically so I couldn't quietly move the goalposts once I saw numbers I liked.

I.Price & token economics

Every decision is four real model calls, and two of them look at an image — vision tokens aren't free. Here's where the three models actually sit, per million tokens:

DeepSeek V4 Pro$0.435$0.87baseline-mix — text stages
Gemini 3 Flash$0.50$3.00baseline-mix — vision stages
MiniMax-M3$0.30$1.20candidate — all four stages

The output-price gap is the interesting part: Gemini's $3.00/M output is currently carrying both vision stages in the baseline mix. Worth being precise about what that figure actually is — Gemini 3 Flash Preview's own pricing lists one input rate covering text, image, and video alike ($0.50/M) and a single output rate ($3.00/M), because this model only ever writes text back; it doesn't generate images, so there's no separate "image price" being paid here. The rate itself doesn't care whether the input was a chart or a sentence — what actually drives cost is how many tokens the chart tokenizes into, not a higher per-token charge for looking at it. If MiniMax-M3 can read the same charts competently, the two most expensive calls in the whole pipeline get a lot cheaper — that's a real, quantifiable incentive to switch, if it holds up under criterion two. MiniMax's rate is also a standing 50% promotional cut off its own list price, which is its own note to self: don't build a permanent cost model on a promotional number.

That list pricing shows up in independent measurement too. Artificial Analysis's per-task cost figures (actual observed spend, not sticker price) put DeepSeek V4 Pro as the cheapest model in its intelligence-benchmark comparison set at $0.04/task, with MiniMax-M3 at $0.12/task — both well below the frontier models they're being weighed against. The gap holds on coding-agent tasks too, where DeepSeek V4 Pro came in at $0.27/task against $2–12+ for the frontier options in that comparison.

II.Capability, measured where it counts

I started with Artificial Analysis's Intelligence Index — a composite across nine evals including GPQA Diamond, Humanity's Last Exam, and MMMU-Pro for visual reasoning, so multimodal capability is already part of what it's measuring, not something I had to check separately. On that index, DeepSeek V4 Pro and MiniMax-M3 land tied at 44. That tie is exactly why this can't be settled by leaderboard alone — general intelligence says "toss-up," which is a real finding, not a non-answer, and it's the reason Phase 1 has to run at all rather than being decided from a chart on someone else's website.

Where it stops being a toss-up is on a benchmark closer to the actual job. Vals AI's Finance Agent v2 — entry-level financial-analyst tasks against real filings — has MiniMax-M3 at 48.27% (rank 17 of 40 models tested) against DeepSeek V4 at 44.08% (rank 24 of 40), with MiniMax-M3 also costing about a third as much per test and running roughly 3x faster on that benchmark. Tied on general intelligence, ahead on the closest available proxy for this task, and cheaper doing it — that's a real reason to take MiniMax-M3 seriously as more than a cost play, not just a hunch.

Sources: Artificial Analysis Intelligence Index; Vals AI Finance Agent v2.

III.Hallucination & inconsistency

This is the one that actually bit me already, in a different form. Early on, the vision agents would occasionally state a support level miles outside what the chart could possibly show — confidently citing a price the y-axis never contained. The fix was to explicitly anchor the prompt to the chart's real close and range before asking for an opinion, which stopped it. That's the category of failure this criterion watches for: not "wrong direction," but the model stating something false about the input it was just shown.

The other half is a subtler kind of inconsistency the backtest surfaced independently: this system's worst losses tend to come from all three specialists agreeing confidently right at a reversal — a unanimous, high-conviction, wrong call. Two of the four architectures (the AutoGen debate and the Reflexion variant) exist specifically because of that finding.

And here's the concrete reason I insisted on re-testing MiniMax fresh instead of carrying over an old impression: on that same Finance Agent v2 benchmark, MiniMax-M2.7 scores 27.89% — rank 38 of 40, near the bottom of the field. MiniMax-M3 scores 48.27%. That's not a minor point release, it's the difference between "avoid this model for finance work" and "genuinely competitive," inside one model generation.

A hallucination or consistency finding from a prior model generation doesn't transfer to the next one — treating it like it does is exactly the kind of shortcut this whole project is trying not to take, and the M2.7-to-M3 jump is the proof it isn't a hypothetical risk.

Source: Vals AI Finance Agent v2 — MiniMax-M3 vs. MiniMax-M2.7.

Why not the other six

Agent frameworks split roughly into four families. Before narrowing to what's actually in Phase 2, it's worth showing the full board — and being honest about which of these nine I've tested versus which I'm characterizing from well-documented, known architecture alone.

The highlighted three are the only ones I've actually run against this task — everything else is scored on well-documented default architecture, not a benchmark I ran, and I'm not pretending otherwise. MetaGPT and AutoGPT specifically were considered and rejected early: MetaGPT is a fixed, software-company-style SOP pipeline — not built for a single recurring trading call — and AutoGPT's open-ended, unbounded task loops are exactly the kind of uncontrolled autonomy a bounded, auditable decision shouldn't be handed to. CrewAI and CAMEL are genuine, capable role-based multi-agent frameworks; they simply were never in this project's actual comparison, so I'm not going to imply they were tested and came up short.

Deferred on purpose

I don't have a favorite architecture yet, and Phase 1 is specifically designed so I don't need one until the model question is settled first. Here's what's actually in the running for Phase 2:

  • LangGraph — the original baseline. Three specialists in parallel, one decision node. No debate, no revision; whatever it decides first is final.
  • AutoGen — the same three specialists as a moderated debate, each forced to state the strongest reason its own read could be wrong before a closing synthesizer rules.
  • DSPy — structurally identical to the LangGraph baseline, but the prompts aren't hand-written — an optimizer searches for the instructions and few-shot examples that maximize realized R on a training window.
  • LangGraph + Reflexion — the baseline plus one addition: a reflector critiques the decision against the same reversal failure mode and can send it back for a bounded number of revisions before it ships.

Worth being honest about: AutoGen's debate and the Reflexion variant are two different answers to the same diagnosed problem — dissent-by-design versus revise-on-critique. If one clearly outperforms the other in Phase 2, that's not just "framework A beat framework B," it's a real result about which failure-correction mechanism actually works better here.

Reflexion, not LATS or plain self-refinement

Self-critique loops aren't one idea, they're a small family, and I picked the middle of three real options:

  • Self-Refine — generate once, critique once, revise once — a single fixed pass, no memory of past attempts.
  • Reflexion — chosen — generate, critique, and revise for a bounded number of rounds, with the critique from each round actually threaded into the next attempt.
  • LATS — Monte Carlo tree search over multiple candidate decisions per step, each branch scored and expanded before one is chosen.

LATS is the one I ruled out deliberately rather than by default, and the reason is specific to this task rather than a general knock on it. LATS earns its cost in domains with a real, cheap intermediate reward to search against — code that can be executed, a fact that can be checked against a retrieved source. A live trading decision has no such signal: you cannot know if LONG or SHORT was correct until real hours of price action actually pass, so there's nothing for the tree search to backpropagate against at decision time. Without that, LATS's branching reduces to repeated self-scoring across a wider, more expensive tree than Reflexion already does directly — likely several times the token cost per decision for a search advantage that depends on a reward signal this task doesn't have available synchronously. Self-Refine, on the other end, is a single fixed pass with no budget to escalate if the first critique isn't enough. Reflexion's bounded, memory-carrying loop was the deliberate middle: enough rounds to actually act on a critique, capped so cost stays predictable.

Right now

Phase 1 is running — five replicates of DeepSeek+Gemini and five of all-MiniMax-M3, same window, same architecture, hit-rate and net R compared once both sets finish, cost and latency captured throughout. This page will get the actual numbers when they exist; I'd rather ship the reasoning honestly incomplete than dress up a guess as a finding.
